# RFC 0319: Bounded DAG Artifact Compiler

Status: implemented; fixed CPU conformance passed at `dc1ce099c138ba383e42077d822275d06937c7b1`.

[PR #115 conformance](https://github.com/kirchherr/TUC/actions/runs/35315459102)
passed static and ASan/UBSan execution and every required control. The
[full CI](https://github.com/kirchherr/TUC/actions/runs/35315459034) passed
4,185 tests with two skips, Ruff and Mypy. These results bind that source
revision; the shared CPU/GPU worker in RFC 0320 is a separate execution boundary.

## Problem and decision

RFCs 0312-0318 established native execution for individual reviewed graphs.
Each experiment contains a fixed emitter and worker. Adding another topology
must now exercise reusable lowering instead of growing another fixed emitter.

Add a pure `lower_bounded_dag(hac_ir, partition, targets)` API in
`tuc.backends.bounded_dag`. It validates typed HAC-IR and the selected partition,
rebuilds the existing canonical residency plan, and emits C11/CUDA primitives,
an integer-only schedule header and a manifest binding their SHA-256 digests.
An explicit closed target map associates selected backends with C11 or CUDA
sm86; target-specific details stay outside HAC-IR. There is no backend discovery,
source ingestion, compiler invocation, library loading or execution in this API.
`validate_bounded_dag_artifacts` independently reconstructs the expected bundle
and requires an exact match before an external wrapper may use its texts.

## Accepted language and budgets

- Static dense row-major float32 tensors, rank one or two, dimensions 1-64.
- Rank-two Matmul, same-shape ReLU and axis-one row Sum without keepdims.
- At most 8 operations, 24 distinct tensors, 48 residency buffers, 96 events,
  256 KiB of planned buffer storage and 1,000,000 scalar arithmetic steps.
- At most 64 KiB of bounded metadata and 256 KiB of emitted artifacts.
- Exact known Python data types, bounded identifiers and metadata structure;
  no arbitrary objects, strings as enums, dynamic dimensions or source fragments.
- SSA and shape compatibility, assignment order and tensor-byte accounting are
  checked before emission. Explicit public return aliases must cover exactly
  the terminal tensors; aliases are preserved separately from tensor identities.

Backend placement and copies come from the existing core planner. Shared
immutable copies can serve multiple consumers. A manifest contains tensor and
buffer identities, bind/copy/execute/publish events, public aliases, source
digests, arithmetic policy and planned work. User names never become C symbols:
generated symbols and schedule references use validated consecutive integers.

## Arithmetic and native caller obligations

Each Matmul computes products and left-to-right sums with a separate binary32
rounding per operation. Sum uses the same ordered addition. C11 uses volatile
intermediates, binary32 compile-time assertions, no fast math, no contraction and
FE_TONEAREST. CUDA uses explicit round-to-nearest multiplication/addition
intrinsics, sm86 SASS only, `--ftz=false` and `--fmad=false`. See the
[CUDA single-precision intrinsic reference](https://docs.nvidia.com/cuda/cuda-math-api/cuda_math_api/group__CUDA__MATH__INTRINSIC__SINGLE.html).

The contract is restricted to finite normal values or zero, including rounded
intermediates; signed zero is numerically equivalent. A native caller must
establish buffer extents, distinct output storage, liveness, correct target and
launch geometry, round-to-nearest and disabled flush-to-zero/denormals-are-zero.
Primitive pointer signatures do not enforce these obligations. No arbitrary
input domain, overflow behavior, error-budget proof or vendor equivalence is
established by source emission or by the small fixed corpus below.

## Validation portfolio

`examples/bounded_dag_compiler.py` emits 36 inert bundles: chain, fanout, fan-in
and a seven-operation DAG, each at three shape triples and three placements.
The last DAG joins two ReLU producers at Matmul, forks its projection to a row
Sum and another ReLU, then joins a third input at a second Matmul and publishes
another row Sum. This topology is not special-cased in lowering.

Pure tests additionally enumerate every CPU/GPU placement of four graphs,
including a different graph with three Matmuls. An independent binary32
reference evaluates original graph semantics and is compared with buffer-slot
schedule replay for 168 placements and three input corpora (504 comparisons).
Tests cover copied-value reuse, return contracts, renaming, schedule/manifest
agreement, budget rejection, malformed types and artifact substitution.

## Narrow native C11 exception

This RFC defines one fixed CPU-only conformance exception. The dedicated
`bounded-dag-proof.yml` job may compile and execute only the twelve repository
family/shape cases generated by `examples/bounded_dag_c11.py`, with all operations
on C11. The worker receives no native plan, source text, input tensors or
selectors at runtime. It preallocates its generated fixed buffers, checks ready
operands and public completion, poisons buffers between runs, and compares
outputs with an independently implemented Python binary32 oracle baked as bits.

The static and ASan/UBSan builds each expect 72 case runs, 324 primitive calls,
1,404 terminal scalar comparisons and 108 publications. Three separately built
fault variants omit an operation, corrupt an output, or omit a publication.
Each variant must reject all twelve cases with its precise reason and exit 1;
timeouts, crashes, sanitizer failures and Docker failures cannot count as a
successful negative control. There are 72 case-level rejections across both
builds. Expected protocol data are synthetic and are never execution evidence.

Isolation is Linux x86-64 with digest-pinned GCC and Dockerfile frontend,
offline build steps, non-root workers, no network, devices, mounts or sockets,
read-only root, dropped capabilities, no-new-privileges and default seccomp.
Workers have one CPU, 1 GiB memory, 32 PIDs, bounded descriptors/output/tmpfs,
an internal 20-second alarm and an external 30-second deadline. The entire CI
job has a 15-minute deadline. The sanitized image includes its runtime; the
ordinary image is scratch with a static executable. No security relaxation
or host installation is introduced. Workflow actions are commit-pinned, the
token is read-only and checkout does not retain credentials.

The acceptor regenerates and verifies the full context, rejects symlinks and
oversized files, then requires exact bounded receipt fields and image IDs.
The stored record binds the context and images; it is not a signature or
independent provenance. CI supplies the run/commit association. The default
Python command remains execution-free and reports native observation false.

## Evidence and remaining boundary

This change adds a reusable compiler pass and a fixed CPU conformance route.
Previously accepted native reports, frozen experiment sources, runtime defaults
and admission gates are unchanged. No existing golden is regenerated to imply
that its old execution covered the new compiler.

CUDA emission is inspectable text only. Physical testing of these new artifacts
requires a separately reviewed concrete wrapper, source/context binding and
fresh explicit dev001 approval. This RFC does not authorize that connection.
General runtime execution, dynamic shapes, new operations/ISA/vendors, parallel
scheduling, performance and independent reproduction remain separate work.

Before merge, require the normal owner review, Python/type/lint suites, existing
proof CI and the dedicated C11 conformance job for the actual proposed revision.
