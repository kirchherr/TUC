## Download and check the offline kit

Open a successful run of the
[bounded model application workflow](https://github.com/kirchherr/TUC/actions/workflows/bounded-model-application.yml)
at the revision being reviewed and download its
`bounded-model-application-audit-kit` artifact. GitHub retains it for 14 days;
the versioned builder can recreate it later from the same committed sources.

After extracting the GitHub artifact into a new directory, verify the ZIP
against its supplied checksum. On systems with `sha256sum`:

```sh
sha256sum -c tuc-model-application-audit-kit.zip.sha256
python -m zipfile -e tuc-model-application-audit-kit.zip offline-audit
cd offline-audit
sha256sum -c CHECKSUMS.sha256
python -I -S audit_native_receipt.py --ci-packet observed-ci-59ad813.json
```

The ZIP contains the current Python auditor, retained original CI packet,
original auditor text, LICENSE, NOTICE, README, `SOURCE.txt` and `CHECKSUMS.sha256`. Compare the
source commit with the selected CI run. The CI builder uses only fixed regular
Git blobs from that commit, sets deterministic ZIP metadata and tests the
extracted package outside the checkout. README and checksum metadata are
generated by the versioned builder. Edits to source input files, local notes
and unexpected archive members do not enter the package.

Success reports 18 scalar checks, four rejection checks, `tuc_imported=false`
and `native_execution_performed=false`. This archive includes Python source;
verify that source against the trusted repository/CI before executing it.
Checksums alone authenticate neither the sender nor the execution observation.

## Remaining independent acceptance

An operator outside the project must supply a fresh observation from an
independently controlled Linux x86-64 environment. The
[native reproduction instructions](../integration/bounded_model_application/README.md)
specify the installed-wheel execution and separate audit. Preserve the exact
source, wheel/source hashes, environment/operator identity, raw record, audit
output and command log, with the origin of that evidence stated explicitly.

Same-project CI, another VM controlled by the same maintainer and local replay
do not satisfy that independent acceptance. They establish reproducibility
readiness. Organizational reproduction remains open until the external
observation is supplied and checked.

Broader model compatibility, other native targets, cross-vendor behavior,
performance and production admission remain separate research obligations in
the master plan. This handoff preserves those boundaries.
